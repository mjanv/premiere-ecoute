# Distribution

`tools/package.sh` builds the release exe and produces `dist/premiere-ecoute-player-<version>-setup.exe` and `-portable.zip`.

- **Static CRT**: `.cargo/config.toml` sets `+crt-static` for the MSVC target, so the exe has no `VCRUNTIME140.dll` dependency and runs on a clean Windows.
- **Icon and version info**: `build.rs` embeds `assets/app.rc` (with `assets/icon.ico`) via `embed-resource`/`llvm-rc`. Regenerate the icon with `python3 tools/gen-icon.py`. Bump the version in `Cargo.toml` and in `assets/app.rc`.
- **Installer**: `installer/installer.nsi` (NSIS, built on Linux with `makensis`). Per-user (`%LOCALAPPDATA%\Programs\premiere-ecoute-player`), Start menu shortcut, uninstall entry. Uninstalling keeps `%APPDATA%\premiere-ecoute-player` and the saved sign-in.
- **Release**: push a `v*` tag, the same one as the Stream Deck release, and `.github/workflows/release-desktop-player.yml` runs `tools/package.sh` on Ubuntu and attaches the installer and the zip to that release. The files are named after the version in `Cargo.toml`, not after the tag, and the job fails if `Cargo.toml` and `assets/app.rc` disagree. The release body is left to the Stream Deck workflow.
- **Release profile**: thin LTO and stripped symbols. Never `panic = "abort"`.
- **Code signing**: `tools/package.sh` signs the exe (before it goes into the zip and the installer) and then the installer with `osslsigncode` (`apt install osslsigncode`) when `SIGN_PFX` points to a `.pfx` file (`SIGN_PFX_PASSWORD` is its password, `SIGN_TIMESTAMP_URL` defaults to DigiCert's). Without `SIGN_PFX` it builds unsigned and says so. **This only suits a test certificate or one issued before June 2023**: since then, publicly trusted code signing keys must live on certified hardware and cannot be exported to a `.pfx`. A certificate bought today means cloud signing instead (Azure Artifact Signing, SignPath for open source, or a CA's cloud service), which needs this step rewritten. The release workflow reads the secrets `WINDOWS_SIGNING_PFX_BASE64` and `WINDOWS_SIGNING_PFX_PASSWORD`; without them the release is unsigned and the job logs a warning.
- SmartScreen: a signature shows the publisher instead of "Unknown publisher", but every new build still warns until it has built reputation through downloads. EV certificates no longer bypass this (Microsoft, [SmartScreen reputation](https://learn.microsoft.com/windows/apps/package-and-deploy/smartscreen-reputation)), so they are not worth the premium for this alone. A self-signed certificate does not help users: only one from a trusted authority counts.
- Not done: auto-update, start with Windows.
